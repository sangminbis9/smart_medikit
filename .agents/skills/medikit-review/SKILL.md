# medikit 변경 검토

[공통 규칙](../../../AGENTS.md)과 [검증 절차](../../../docs/CONTRIBUTING.md)를 읽고, [plan.md](../../../plan.md)의 관련 요구사항 및 [계약 초안](../../../docs/CONTRACTS.md)을 기준으로 검토한다. 아래 항목 중 변경 범위에 해당하는 것만 점검하며 확정 정책과 구현 제안을 구분한다.

1. 함수·메서드·생성자·콜백 앞 간결한 한국어 설명과 중요 분기 주석, TypeScript/React 명명, 중복 코드·불필요한 파일 분리를 확인한다. 문서 변경은 실행 가능한 코드처럼 검증했다고 보고하지 않는다.
2. Pi↔AWS↔React/Service Worker의 API·이벤트·상태를 바꾸면 계약·관련 호출부·검증 항목을 함께 맞춘다. 사용자가 문서만 지정했다면 구현을 확장하지 않고 후속 불일치를 보고한다.
3. 카메라 최초 등록, event_id 멱등성·sequence 순서·Pi 오프라인 큐, 재반입 중복 차감 방지, 후보 포장+반입/반출/변경 없음 확인과 최초 응답 일관성을 확인한다.
4. 예상 복용/재고와 실제 복용, 처방약 봉투 회분과 개별 정수, 실제 만료일과 임시 기준일을 구분한다. 정제·캡슐 외 잔여량 미표시, 60분 재알림 1회, 보관 약품 DUR와 KST 당일 반출 교차검사·반복 위험 경고를 유지한다.
5. 기존 Figma 기준 PC·Android·iPhone 반응형 화면과 React 직접 연동 Three.js의 기존 기능·포장/추정 좌표 구조를 확인한다. WebSocket 재연결·화면 복귀·알림 클릭 후 재조회와 오프라인 정정의 미완료 표시를 점검한다.
6. Lambda의 Web Push/VAPID 발송·DynamoDB 브라우저별 구독, 권한 거부·해제·만료·재시도·중복 표시를 확인한다. iPhone의 iOS 16.4 이상 홈 화면 PWA·사용자 동작 기반 권한 조건과 일반 Safari 제약을 구분하고, 실제 도착 시각·수신/읽음을 보장하지 않는다. 예약은 EventBridge Scheduler에 유지한다.
7. 웹 촬영/파일 선택·개인정보 제거·임시 S3·기존 Lambda/PaddleOCR·사용자 확인을 점검한다. 보완 OCR과 Pi 이벤트를 분리하고 성공·실패·취소·중단 작업의 원본 정리, 민감정보 캐시/로그 미저장을 확인한다.
8. Amplify Hosting·GitHub HTTPS 배포, SPA 링크·Service Worker 갱신, CORS/접근 제어 및 IAM·VAPID 비밀키의 웹 번들/빌드 변수 미포함을 점검한다. 시연용 무로그인을 공개 쓰기 허용으로 해석하지 않는다.
9. 가능한 포맷·타입/정적 검사·테스트·빌드 또는 문서/계약 검증 결과를 확인하고, 미실행 사유와 실기기 검증 범위를 기록한다. 결과는 한국어로 문제점(중요도·파일·근거) / 검증 결과 / 남은 위험 순서로 보고하며 문제가 없으면 명시한다.
