# 진료용 약품 보고서 — 확정 설계 (2026-11-15 갱신)

## 목적과 승인된 변경

한 사람이 사용하는 기존 AWS 연동 웹에서 진료 시 보여줄 약 목록을 만든다. 이전 날짜별 선택·회차/추정 요약 대신 **처방 카드와 반출 약품 목록**으로 단순화한다.

## 화면과 선택

- 기존 복약 탭의 버튼으로 `/schedule/report`에 진입한다. 기존 민트 디자인·둥근 버튼·휴대폰 반응형·48px 화살표 터치 영역을 유지한다.
- 상단 최근 1·3·6개월/직접 설정(기본 1개월)을 유지한다. KST 날짜 양 끝을 포함한다.
- 선택/보고서는 **복용 중인 처방약 / 약통에서 반출된 약품** 두 분류다.
- 처방 하나를 카드 하나로 표시한다. 처방명·등록한 공통 시작일~종료일 양 끝 포함 **N일분**·등록된 포함 약 이름/함량 전체를 표시한다. 종료일이 없으면 **상시 복용 중**이다. 명시적으로 종료 처리한 처방은 ‘복용 종료’를 우선 표시한다. 조회 기간·복용 요일·하루 횟수·확인 기록으로 일수를 조정하지 않는다.
- 조회 기간과 공통/약별 일정이 겹치는 처방을 포함한다. 일정 없는 등록도 보존하고 조회 시작일 전에 종료 처리한 처방은 제외한다. 동명 처방은 ID로 분리한다. 약이 없으면 ‘개별 약 정보 없음’을 표시한다.
- 보관함은 반출 이력에 있는 약품만 표시하고 확정 단일 제품 코드 또는 포장 ID 기준으로 반복 기록을 합친다. 현재 재고만 있는 약·추측한 제품·약별 임의 수량은 추가하지 않는다.
- 체크 단위는 처방 카드/보관함 약품이며 기본 모두 선택한다. 선택 완료 후 체크한 항목만 동일한 간단 목록으로 보여준다. 빈 분류는 보고서에서 숨긴다.
- 날짜별 내역·펼치기·일정 기반 추정·예정 시각·복용 횟수·성분 표시는 제거한다. 등록 처방과 반출 이력은 실제 복용 확인 자료가 아니라는 안내를 표시한다.
- 보고서 `←`는 기간·제외 선택을 유지한 선택 화면으로 복귀해 양쪽 출처를 최신 조회한다. 선택 화면 `←`는 복약 화면으로 이동한다. 별도 선택 수정 버튼은 없다.

## 접근 방식

기존 별도 보고서 경로와 읽기 전용 접근을 재사용한다. 원본 복용 이력을 수정하거나 새 회차/보고서 API를 만드는 대신 프론트엔드 카드 계산만 교체한다. 사용자 요청에 따라 날짜별 확인을 숨기기만 하는 방안이 아니라 생성 자체를 제거한다.

## 데이터·안전 경계

- 처방은 기존 인증의 `readSnapshot()`/`GET /medications`에서 읽는다. `state.records`의 부분 복용으로 포함 약을 빼거나 예정 회차를 만들지 않는다. 이름만 보여주기 위해 제품/성분 API를 조회하지 않는다.
- 반출은 기존 `GET /activity`의 `history`/`pending`을 사용한다. KST `occurredAt`으로 조회 범위를 필터하며 `recordedAt`을 실제 섭취일로 해석하지 않는다. 미복용·미확인도 오직 반출 목록으로 사용한다.
- 기존 Y/N·재고·복용 기록 저장·인증/공개 시연 정책을 변경하지 않는다. 새 API·AWS 자원·의존성·PDF·인쇄·외부 공유·개인정보 입력은 추가하지 않는다.
- 선택 완료 시 목록과 기간을 메모리에 고정한다. 기간 변경·명시적 새로고침·재진입은 선택을 초기화한다. 한 출처라도 실패·잠금·미설정·오프라인이면 정상 보고서 생성을 막는다.
- 응답 검증·`no-store`를 유지하고 원본·선택·보고서를 URL/로그/영구 저장소/오프라인 캐시에 추가하지 않는다. 테스트에는 합성 자료만 쓴다.

## 검증

양 끝 포함·같은 날·윤년·상시 복용 중, 조회 기간 겹침·약별 예외·동명 처방 분리, KST 반출 필터·반복 합치기·원본 불변을 단위 검증한다. 기본 선택·제외·최종 간단 목록·기간·복귀·최신 조회·한쪽 실패·오프라인·좁은 화면·쓰기 0건을 E2E로 확인한다. 날짜 상세·추정·제품 조회가 없음을 검증한다. 실제 운영 배포 확인과 로컬 검증을 구분한다.
