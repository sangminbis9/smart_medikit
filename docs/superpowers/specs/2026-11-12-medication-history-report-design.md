# 진료용 복용 이력 보고서 — 설계안

상태: 사용자와 설계를 확정했고 로컬 구현·합성 검증을 완료했다. 실제 AWS 데이터·배포 사이트 검증은 별도다. 기존 복용 기록을 조회하는 작은 웹 기능 추가이며 새로운 섭취 감지·기록 저장 기능은 만들지 않는다.

## 목적과 확정한 요구사항

- 약통 한 대를 한 사람만 사용한다. 진료 중 휴대폰으로 최근 복용 기록을 보여주는 용도다.
- 기존 AWS 연동 React 웹의 디자인과 반응형 구성을 유지한다.
- 복약 탭의 ‘진료용 보고서’ 버튼으로 별도 화면에 진입한다.
- 상단에 ‘최근 1개월 / 최근 3개월 / 최근 6개월 / 직접 설정’을 둔다. 기본은 최근 1개월이며 직접 설정에서는 시작일·종료일을 변경한다.
- 보관함 반출 후 Y로 확인한 기록과 수동 처방약의 전체·일부 복용 확인 기록을 포함한다. 후속 사용자 요청에 따라 수동 등록 일정은 확인 기록이 없어도 현재 조회 기간 안의 지난 예정 회차를 ‘일정 기반 추정’으로 추가한다.
- 미복용·확인 보류·미래 회차·필요 시 복용은 자동 추가하지 않는다. 일부 복용은 선택한 약만 포함하고, 같은 회차의 사용자 확인을 추정과 중복하지 않는다. 수동 미확인 일정의 지난 회차만 추정하며 보관함 확인 대기는 여전히 제외한다.
- 복용 기록 한 건마다 기본 선택된 체크박스를 제공한다. 해제하면 보고서에서만 제외하며 원본 기록은 변경하지 않는다.
- 약 이름, 기록에 연결된 날짜, 확인된 복용량이 있는 경우 해당 복용량, 확인된 성분 정보가 있는 경우 해당 성분을 표시한다.
- 선택 단계에서는 날짜별 전체 기록을 스크롤하며 건별 체크를 해제하고 ‘선택 완료 · 보고서 보기’를 누른다. 보고서에서는 선택된 기록을 약별로 묶어 ‘기록 기간 / 확인 N회’로 요약하고 날짜별 상세를 펼칠 수 있다.
- 체크 해제는 기존 복약 화면이나 `/activity` 쓰기가 아니라 보고서 전용 선택이다. ‘선택 수정’으로 돌아가도 체크 상태를 유지한다.
- PDF·인쇄·외부 공유·별도 앱·별도 사이트는 만들지 않는다.

## 검토한 접근 방식

1. 기존 복약 탭의 버튼에서 별도 보고서 화면으로 이동: 복약 화면의 복잡도를 늘리지 않고 검토와 진료용 표시를 구분한다. 사용자가 이 방식을 선택했다.
2. 기존 복약 화면 하단에 보고서 영역을 추가: 이동은 줄지만 달력과 기록에 이어 화면이 길어져 선택하지 않았다.

## 구현 제안

아래 세부 사항은 구현자가 제안한 기본값이며 사용자 승인 시 적용한다.

- 경로는 `/schedule/report`로 두며 기존 복약 내비게이션을 유지한다. 두 이동 링크는 기존 등록 버튼과 같은 배경색·둥근 모서리에 17px 글씨와 48px 이상의 터치 높이를 사용한다.
- 기록을 선택하는 상태와 선택된 기록만 보여주는 읽기 전용 상태를 같은 화면에서 전환한다. 다시 선택으로 돌아가도 선택을 유지한다.
- 선택 완료 시 기록과 조회 기간을 메모리에 함께 고정한다. 선택 수정에서는 양쪽 기록을 다시 읽되 체크는 유지한다. 명시적 새로고침에서는 두 출처의 최신 응답 완료 전 생성을 막고 선택을 초기화한다.
- 날짜는 KST 기준이며 양 끝 날짜를 포함한다. 최근 1·3·6개월은 해당 개월 수 이전의 같은 날짜부터 오늘까지이며, 해당 날짜가 없으면 그달 말일로 맞춘다.
- 화면에는 날짜를 표시하고 수동 일정은 ‘09:00 예정’처럼 예정 시각도 표시하되 실제 섭취 시각이라고 적지 않는다. 보관함 기록은 ‘반출 날짜’, 수동 기록은 ‘일정 날짜’로 명확히 구분한다. 확인 시각도 실제 섭취 시각으로 바꾸지 않는다.
- 수동 처방 회차에 여러 약을 복용했다면 약별로 선택할 수 있다. 개별 약 정보가 없는 묶음은 묶음명과 ‘개별 약 정보 없음’을 표시하며 특정 약·성분·수량을 추정하지 않는다.
- 수동 처방에 입력한 복용법·복용량은 입력된 정보로 표시하며 실제 측정량이라고 표현하지 않는다. 공식 제품의 일반 용법이나 성분 함량을 개인의 복용량으로 대체하지 않는다.
- 제품 코드 등 기존의 명확한 연결로 확보된 성분만 표시한다. 이름으로 성분이나 항생제 여부를 추측하지 않으며 미확인 후보 제품의 성분을 확정 정보로 사용하지 않는다.
- 같은 약의 선택된 기록을 약별로 요약하되 이름만 같은 다른 제품·함량을 합치지 않는다. 품목코드 또는 동일한 기존 약 식별자로 연결된 경우만 같은 그룹으로 처리하고 근거가 없으면 분리한다. 출처가 다른 확인 기록을 자동 중복 제거하지 않는다.
- 기간 변경으로 조회 대상이 바뀌면 해당 기간의 기록을 기본 선택으로 초기화한다. 선택은 화면 메모리에서만 유지하고 서버나 브라우저 영구 저장소에 저장하지 않는다.

## 데이터와 변경 범위

- 보관함 기록: 기존 `GET /activity`의 `history`에서 `TAKEN`만 조회한다.
- 수동 처방 기록: 기존 `useMedicationPlans`와 `GET /medications`의 상태 및 `occurrencesOnDay`를 재사용한다. 추정은 현재 조회 기간과 등록 일정이 겹치는 범위에서만 계산하고 사용자 확인/추정 횟수를 분리한다. 인증·시연 모드를 우회하지 않는다.
- 기존 복약 화면과 보고서가 같은 응답 검증·주소 검증을 사용하도록 필요한 최소 조회 코드를 공유한다. 새 API·DynamoDB 테이블·AWS 리소스는 만들지 않는다.
- 기존 인증을 재사용하는 프론트엔드 `readSnapshot()`으로 최신 수동 기록을 읽는다. 제품 조회 전후 revision과 상태가 다르면 기존 약에 새 성분을 연결하지 않고 보고서 생성을 보류한다.
- 기존 Y/N 확인, 수량 차감, 수동 기록 저장·수정·삭제 동작은 바꾸지 않는다. 이미 삭제되거나 수정으로 제거된 과거 기록을 복원하거나 별도 장기 보존하는 기능은 범위 밖이다.
- 기존 공개 시연/비공개 접근 정책을 그대로 따른다. 새 개인 식별정보 입력·서버 저장·외부 공개 링크는 추가하지 않는다. 실사용 개인정보 보호가 새로 제공되는 것은 아니며 테스트에는 합성 데이터만 쓴다.
- 보고서 데이터는 로그·URL·Service Worker 캐시·브라우저 영구 저장소에 남기지 않는다. 조회는 `no-store`를 유지한다.
- 한 출처라도 조회 실패·잠금·미설정이면 불완전함을 명시하며 전체 기록을 확인한 정상 보고서로 표시하지 않는다. 빈 기록과 조회 실패를 구분한다.

## 검증 기준

- 실제 복용 확인 기록만 포함하고 일부 복용·개별 정보 없음·날짜 경계·전월 말일·선택 제외를 단위 테스트한다.
- 기존 복약 탭에서 보고서 진입, 기간 변경, 기록별 선택 해제, 선택된 기록만 표시, 돌아가기, 조회 실패·빈 결과를 브라우저 테스트한다.
- 보고서 조작이 쓰기 API를 호출하지 않는지 검증하고 기존 복용 확인 회귀를 확인한다.
- 타입 검사·린트·단위 테스트·빌드와 관련 E2E를 실행한다. 휴대폰 너비에서 가로 넘침과 버튼 접근성을 확인한다.
- 구현 시 `plan.md`, `docs/CONTRACTS.md`, 프론트엔드 안내의 관련 범위만 갱신한다. AWS 실제 배포·실기기 검증 여부는 실행한 범위와 구분해 보고한다.
