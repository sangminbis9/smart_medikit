# 포장 OCR 재판독 개선 — 승인된 설계

사용자는 2026-11-24 대화에서 아래 기준으로 수정본 제공을 승인했다. 운영 AWS 배포는 하지 않는다.

## 목표와 변경 경계
- 최신 GitHub `main`을 기준으로 인식·제품 대조만 개선한다.
- S3 키, 파일명, `event-id`·`session-id`·`sha256`, 단계 JSON, DynamoDB 키·저장 형식·멱등성, 성분/허가정보 보완은 유지한다.
- 원본 OCR과 API 대조가 실패하면 제품 영역 2배·4배 확대 및 기울기 보정으로 다시 판독한다. 최대 픽셀·OCR 횟수·남은 Lambda 시간·API 호출 한도로 종료한다.
- 문구 각도와 위치로 양옆 또는 가까운 위아래 제품명 조각을 결합한다. 기울기가 다른 문구나 떨어진 제품은 결합하지 않는다.
- 세로 영어는 제품명 후보에서 제외한다. 증상·효능·제조사·가격·단독 수식어는 제품 검색어로 쓰지 않는다.
- 영어는 검증된 영문↔한글 제품명 대응을 우선한다. 일반 기계번역으로 임의의 약품명을 만들거나 새 유료 번역 서비스를 추가하지 않는다. 지원 범위는 명시한다.
- 검색 결과가 있다는 사실만으로 성공시키지 않는다. 공식 이름·관측 제형·함량과 단일 품목을 검증하고, 제형 누락/의약외품을 다른 제품으로 확정하지 않는다.
- 다중 품목·확정 충돌·실제 API 연결 장애를 무결과로 숨기지 않는다. 한도 소진·미확정은 기존 확인 대기/실패 계약으로 반환한다.
- 동일 검색어는 캐시하고 과다 검색어는 더 구체적인 조합이나 다른 영역으로 전환한다. 원문·검색어·이미지는 운영 로그에 남기지 않는다.

## 접근 방식
1. 기존 PaddleOCR·OpenCV와 식약처 API를 유지하는 단계별 재판독을 채택한다. 기존 런타임과 저장 계약을 보존하면서 검증 가능하다.
2. 외부 생성형 모델/번역 API 교체는 채택하지 않는다. 새 인증·비용·불확실한 약품명 생성이 필요하다.
3. 임계값 인하·검색 결과 하나 강제 선택·무한 반복은 채택하지 않는다. 오등록과 Lambda 강제 종료를 유발할 수 있다.

## 검증과 산출물
- 실패 회귀를 먼저 실행한 뒤 최소 코드를 수정한다. 전체 OCR 테스트, 관련 배포/저장 호환 테스트, 정적 검사를 실행한다.
- 실제 모델 검증과 모의 OCR/API 단위 테스트를 구분한다. 관찰하지 않은 정확도 향상을 주장하지 않는다.
- 변경 소스와 적용용 ZIP/적용 설명서를 제공한다. 기존 운영 ZIP을 통째로 대체하거나 자동 배포하지 않는다.
