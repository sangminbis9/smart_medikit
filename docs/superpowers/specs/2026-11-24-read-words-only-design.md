# 읽힌 문구 기반 포장 검색 설계

## 사용자 기준
- 사용자가 수정·ZIP 제공을 요청했고 결합 방식은 구현자 판단에 맡겼다. 후속 명시: 읽힌 문구만 검색하며, 여러 API 결과는 실제 읽힌 제형으로만 좁힌다.
- 제품 검색과 결합은 OCR 점수 0.9 이상만 사용한다. 개별 문구 → 다른 개별 문구 → 공간적으로 가까운 결합 문구 → 확대 재검출 순서다.
- 모드코 검색의 여러 결과를 이름 줄기 필터로 시럽 하나만 남겨 확정하지 않는다. 여러 결과면 실제 관측 제형·함량으로만 좁히고, 여전히 여러 개면 재검출한다.
- 영문 한 글자는 한글 발음 표기로 바꿔 인접 상표에 결합한다. 긴 세로 영문은 제외하되 세로로 긴 단일 S는 버리지 않는다. 가로 긴 영문은 검증된 상표 대응만 사용한다.
- 실제로 읽히지 않은 슈퍼자임 등의 단어를 API 후보에서 가져와 검색하거나 오타를 자동 교정하지 않는다.

## 접근
기존 문서/다품목 matcher를 크게 바꾸기보다 Pi 전용 검색을 `package_matching.py`로 분리한다. 이 모듈은 검색 순서·공간 결합·관측 속성에 의한 결과 선택을 맡고 기존 PackageReader는 영상·재판독·운영 정보 보완을 유지한다. 기존 API 전송·공식 성분 괄호 검증은 재사용한다.
- 필터링하지 않는 기존 방식은 잡음이 제품명을 막으므로 제외한다.
- 유사도 교정·API 정답 역주입은 사용자의 읽힌 문구 원칙에 반하므로 제외한다.
- 범용 유료 번역 서비스/임의 의약품명 음역은 추가하지 않는다. 미지원 영문은 확정하지 않는다.

## 안전·비목표
S3 파일명·메타·DB·Pi·저장 계약 불변. 의약외품 차단의 저신뢰 표시는 API 검색/결합에 쓰지 않는 별도 보수적 안전 신호로 유지한다. API 응답 스키마/의약품 제형은 출력에 필요하지만 읽히지 않은 제형을 후보 선택에 사용하지 않는다. 복수 독립 약품·관측 속성 충돌·불완전한 API 결과·네트워크 오류를 숨기지 않는다.
OCR 최대 4회, 입력/회전 2048px, 새 대조 API 64회·고유 검색어 32개, 시작 전 30초 여유 유지. 기존 legacy_api 보완 호출은 별도다. 실제 AWS 배포·S3 재업로드·DB 수정은 이번 요청에 포함하지 않는다.
